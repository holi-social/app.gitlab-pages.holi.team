## Frontends

- **Mobile:** the mobile application is based on React Native and contains HOLI clients for both
  Android and iOS.
- **Web (SPA) & Web (SSR):** the web version of HOLI is based on Next.js / React
- Both mobile and web use a high degree of code sharing by leveraging
  [react-native-web](https://github.com/necolas/react-native-web) which allows React components to be
  written using the React Native way (i.e. using its library) but also to be
  run on Web. The rough idea is that every screen and business logic is written in a cross-platform
  way that will run on both web and mobile. Only platform-specific stuff (e.g. Navigation) has to be
  written in a platform-specific way. Both mobile and web applications live in the
  [holi-frontends](https://gitlab.holi.team/app/holi-frontends) monorepo.

## Identity and Access Proxy (Ory Oathkeeper)

HOLI uses [Ory Cloud](https://www.ory.sh/cloud/) as an identity provider. Oathkeeper is an API gateway (aka
reverse proxy) that can enforce authentication and optionally authorization for backend services.
See [Authentication & Authorization](../authentication-authorization) for more details. The deployment
and configuration code is contained in the [holi-unified-api](https://gitlab.holi.team/app/holi-unified-api)
repository (also see below).

## Unified API (GraphQL Mesh)

[holi-unified-api](https://gitlab.holi.team/app/holi-unified-api) is (another) API gateway that provides
HOLIs GraphQL API towards frontend and internal clients. The GraphQL API itself is a federated API that
stitches together multiple (GraphQL / REST / ...) APIs to offer a single well-defined and -typed
entrypoint.

## Social Core (okuna)

[holi-okuna](https://gitlab.holi.team/app/holi-okuna) is a fork of the social network called "Okuna"
(earlier: "Openbook") which started as a Facebook clone/competitor. Okunas development has recently
been discontinued but its sources still provide the HOLI project with a good starting point to develop
its "social features" upon. Examples: user profiles, connections, posts.

## Chat

### Matrix Chat Server (Synapse)

[holi-chat-server](https://gitlab.holi.team/app/holi-chat-server) contains the Synapse homeserver provided
by [Matrix](https://matrix.org/), a decentralised and real-time communication server. It uses the same
Postgres instance that we are using for Okuna. The users are created using a unique identity created during
the account creation and stored in Ory (owner of the identities) and Okuna (to be able to synchronize the
data between the chat users and their profiles stored in Okuna), see
[Registration & Login](../authentication-authorization/registration-login) and
[Integrations](../authentication-authorization/third-party-integrations) for details.

### Matrix Push Gateway (Sygnal)

Also to be found in [holi-chat-server](https://gitlab.holi.team/app/holi-chat-server) is Sygnal, the
reference implementation of the Matrix [Push Gateway API](https://spec.matrix.org/v1.7/push-gateway-api/).
The Matrix homeserver forwards message events to the push gateway which will then take care of the
delivery to Apple Push Notification Server (APNs, iOS) and Firebase Cloud Messaging (FCM, Android). Push
Notifications are directly delivered to the device, and either directly displayed (app closed) or passed
through to the app via [expo-notifications](https://docs.expo.dev/versions/latest/sdk/notifications/).

## App Integrations

HOLI is planning to integrate a larger number of third party services in the future. The expectation is
that each of those integrations will have zero, one or more backend services within HOLIs runtime
architecture itself. Current integrations are:

### Donations

[holi-app-donations](https://gitlab.holi.team/app/holi-app-donations) contains the backend for the
integration of [Betterplace.org](https://betterplace.org). The frontend is part of the
[holi-frontends](https://gitlab.holi.team/app/holi-frontends) monorepo.

### GoodNews

[holi-app-goodnews](https://gitlab.holi.team/app/holi-app-goodnews) contains the backend for the
integration of [GoodNews](https://goodnews.eu/). The frontend is part of the
[holi-frontends](https://gitlab.holi.team/app/holi-frontends) monorepo.

### Volunteering

[holi-app-volunteering](https://gitlab.holi.team/app/holi-app-volunteering) contains the backend for the
integration of [Voltastics](https://voltastics.com). The frontend is part of the
[holi-frontends](https://gitlab.holi.team/app/holi-frontends) monorepo.

### Events

[holi-app-events](https://gitlab.holi.team/app/holi-app-events) contains the backend for the

[Joint Action for Sustainable Development](https://gemeinschaftswerk-nachhaltigkeit.de).
The frontend is part of the [holi-frontends](https://gitlab.holi.team/app/holi-frontends) monorepo.

## Shared Services

Some services are of such a generic nature that they can be sensibly shared between core and integration
services or even frontend applications.

- [holi-geo-api](https://gitlab.holi.team/app/holi-geo-api) provides geo-coordinate resolution and places
  auto-completion
- shared-image-proxy is a proxy server that allows to transform images from 3rd party sites on-the-fly
  (e.g. to use sensible image resolutions within the holi mobile/browser app). Currently, it is barely a
  deployment of [imgproxy](https://imgproxy.net).

## Pub/Sub

HOLIs chosen integration technology is a Pub/Sub network. Currently, this is
[Google Cloud Pub/Sub](https://cloud.google.com/pubsub/). Events are defined in
[Integration Events](../integration-events). All services may publish and/or consume events.

## Data Pipelines / Recommendation Service

holi uses Machine Learning technologies to calculate recommendations and other types of personalization
for its users. For this several data pipelines optionally have access to data within various Postgres
databases, receive domain events from the internal Pub/Sub and can run arbitrary computations using Google
Cloud services like Google Cloud Run jobs. The resulting recommendations are then stored in a Postgres DB
to be served to end users by the Recommendation Service.

Go to [Machine Learning](./machine-learning) to learn more about holis data pipelines and recommendation
service.

## Postgres / PostGIS

Any service may use Postgres / PostGIS databases for data persistence. Currently, all services share one
[Google Cloud SQL](https://cloud.google.com/sql/docs) Postgres instance, but databases are to be separated
per service.

## Novu Notifications

We use an EU-hosted variant of [Novu](https://novu.co) to deliver in-app notifications, mobile push notifications and emails to our users.

To forward the required data, our social core (Okuna) subscribes user emails and push tokens to novu as a side effect of handling users and their social interactions.
The mobile clients [receive push messages](../push-notifications) via platform-specific providers.
All clients connect to novu cloud [securely](../authentication-authorization/third-party-integrations#securing-the-notification-content) to fetch and acknowledge In-App notifications and allow users to manage their notification preferences.

## Translation / LibreTranslate
holi integrates [LibreTranslate](https://github.com/LibreTranslate/LibreTranslate), an open-source machine translation API, to handle translation tasks within the app. 

- [holi-translation-api](https://gitlab.holi.team/app/holi-translation-api): Manages requests and interactions with the translation service, enabling users to request translations of posts, comments, and other text content.
- [holi-libretranslate](https://gitlab.holi.team/app/holi-libretranslate): Deploys and maintains the self-hosted [LibreTranslate](https://github.com/LibreTranslate/LibreTranslate) service.
